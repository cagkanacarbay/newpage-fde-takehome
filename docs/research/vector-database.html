01 This is a deployment choice

At this local-corpus scale, the store does not decide retrieval quality.

LlamaIndex can fuse a dense retriever and a BM25 retriever in application code. Native hybrid search is useful, but it is not required.

The useful axes are Docker weight, LlamaIndex support, and the managed upgrade path.

LanceDB

LanceDB adds no service to Docker. Its LlamaIndex integration exposes vector, full-text, and hybrid query modes.

The current integration does not support its hybrid path against LanceDB Cloud tables.

Hybrid search · LlamaIndex integration

SimpleVectorStore

This is the smallest honest baseline. It adds no dependency and persists to a JSON file.

Hybrid retrieval would use LlamaIndex’s QueryFusionRetriever with a separate BM25 leg.

Qdrant

Qdrant has the strongest server-side hybrid story and a clean managed path. Its image is about 67 MiB compressed.

Hybrid queries · LlamaIndex guide

Options not shortlisted

pgvector adds a full database server before the application needs Postgres. Chroma lacks native hybrid search in its open-source version.

sqlite-vec has no LlamaIndex adapter and remains pre-v1.

03 Shortlist and decision

  1. LanceDB - selectedEmbedded, natively hybrid, Apache-2.0, and supported by LlamaIndex.
  2. SimpleVectorStoreMinimal fallback. It proves the RAG loop with no storage infrastructure.
  3. QdrantUse it if the design needs a service boundary or a stronger managed path now.
Decision

Use LanceDB for the local Docker demo. It adds no service, supports native BM25 plus dense search, and has a mature LlamaIndex integration.

LanceDB Cloud does not currently support the hybrid path through this integration. Revisit the managed choice when deployment becomes real.

04 Revisit triggers

  • Compare Qdrant Cloud and LanceDB Cloud when the deployment target becomes concrete.
  • Reconsider pgvector if Postgres enters the stack for chat history or users.
  • Reconsider a server when the corpus outgrows embedded storage.
