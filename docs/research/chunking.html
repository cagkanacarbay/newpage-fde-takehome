Use Docling's document structure to make searchable chunks with contextual text and exact source locations.

01 Use Docling HybridChunker with flat retrieval

The parser should decide semantic boundaries. The embedding tokenizer should only split an oversized structural unit.

Use HybridChunker on the native DoclingDocument, with the selected embedding tokenizer and repeated table headers.

Use DoclingReader(export_type="json") and DoclingNodeParser so headings, paragraphs, lists, tables, captions, page numbers, and bounding boxes remain available to the node layer.

Add a narrow application adapter for stable IDs, contextual text, and exact source provenance.

Decision boundary

This page records a provisional integration shape. The final chunking decision depends on the listed corpus tests.

The missing gate is a retrieval benchmark on the 27-paper corpus with the selected embedding model.

Parent-section expansion is outside this demo. Add it only when the system is productionized.

02 Candidate landscape

The useful design space has three layers: document-native chunkers, optional hierarchy builders, and retrieval adapters.

Why fixed-token splitting is not the primary strategy

Token splitters can be useful safety valves, but they do not know whether a line is a heading, a table row, or a caption.

Docling's native hierarchy creates one chunk for each detected element and merges list items by default.

Its hybrid layer splits only oversized chunks and merges undersized peers when headings and captions match.

04 Verified Docling and LlamaIndex integration path

The official extension has a JSON-preserving reader and a node parser that delegates chunking to a Docling BaseChunker.

  1. Parse the PDF onceUse DocumentConverter with the approved heading hierarchy option. Store the native DoclingDocument JSON as the ingestion artifact.
  2. Read native JSON into LlamaIndexInstantiate DoclingReader(export_type="json"). The reader creates a LlamaIndex Document whose text is serialized Docling data.
  3. Create searchable chunksInstantiate DoclingNodeParser(chunker=HybridChunker(...)). The parser creates nodes for Docling paragraphs, headings, tables, and other document elements.
  4. Attach stable retrieval metadataWrite document_id, chunk_id, heading_path, doc_item_refs, page numbers, bounding boxes, and a content hash.
  5. Index searchable chunksEmbed and add contextualized chunk text to dense and BM25 indexes. Keep original chunk text separate from generated context.
  6. Return source chunksKeep the winning chunks and their original Docling provenance in the retrieval result. Do not expand them to larger sections in the demo.
Minimal verified wiring 
from docling.chunking import HybridChunker
from llama_index.node_parser.docling import DoclingNodeParser
from llama_index.readers.docling import DoclingReader

reader = DoclingReader(export_type="json")
chunker = HybridChunker(tokenizer=embedding_tokenizer)
parser = DoclingNodeParser(chunker=chunker)

documents = list(reader.load_data(pdf_path))
children = parser.get_nodes_from_documents(documents)

The official API confirms that DoclingNodeParser accepts any Docling BaseChunker and places the exported chunk metadata on each LlamaIndex node.

Productionizing follow-up

A document store and section expansion layer may improve context at production scale.

The current application bridge preserves source provenance on paper 009. Do not build section expansion for this demo. Reassess it during productionizing with a measured retrieval and context-size test.

05 Contextual retrieval and demo scope

Demo retrieval

Retrieve and rank flat Docling chunks in the dense and BM25 indexes.

Keep each chunk's original text, stable ID, heading path, page number, bounding box, and item references.

Return the source chunks directly. The demo does not add a document store or section expansion.

Contextual text

First add deterministic context: paper title, section path, element type, table caption, and page label.

Then test generated context as a separate experiment. Cache it by document hash, child hash, prompt version, and model version.

Index the generated context plus chunk text, but show only the source chunk and its provenance to the researcher.

Productionizing only. A future production system can test section storage and context expansion. This demo does not need that complexity.

Citation rule

Generated context can improve retrieval. It cannot create a page citation or replace the original Docling provenance.

Anthropic's published contextual retrieval method prepends 50 to 100 generated tokens before dense and BM25 indexing.

Its benchmark used the whole document and the target chunk to generate context, then measured retrieval failure at top 20.

Still required before closing the choice

  • Run the same six retrieval cases from the evaluation page with flat and hybrid chunks.
  • Measure gold-paper recall at top 5, top 10, and top 20, plus distractor rank.
  • Assert that every returned chunk has a document ID, chunk ID, page number, bounding box, and heading path.
  • Compare deterministic context with generated context on dense retrieval and BM25 separately.

07 Recommendation, risks, and revisit triggers

Provisional decision for testing

Use Docling HybridChunker as the primary chunker. Pass the selected embedding tokenizer, keep table headers on split table chunks, and preserve the native metadata.

Use LlamaIndex DoclingReader and DoclingNodeParser as the integration seam. Keep retrieval flat, preserve source metadata, and add only the contextualizer needed for the demo.

Start with deterministic contextual text. Add generated context only behind a versioned cache and an evaluation flag.

Defer section expansion. Treat document-store-backed context expansion as productionizing work.

Revisit triggers

RiskControlRevisit trigger
A section or table is larger than the embedding limitLet HybridChunker split only that unit and repeat the heading or table header.A corpus benchmark shows lost table rows or lower recall than a controlled overlap baseline.
Docling loses a caption or reading-order relationKeep the native item refs and add a regression PDF for each observed defect.A required query cannot recover its table, caption, or neighboring evidence.
Node metadata loses page or box dataFail ingestion when required provenance is absent from a searchable chunk.The direct LlamaIndex propagation test fails on any finalist PDF.
Generated context adds a false claimKeep generated text out of citation display and store model and prompt hashes.Context improves rank but changes the answer against the source text.

The recommendation should become a recorded decision only after the local retrieval and provenance gates pass.
